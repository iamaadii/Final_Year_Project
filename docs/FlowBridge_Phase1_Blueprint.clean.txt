1. Executive Summary
FlowBridge Phase 1 is an AI-powered financial operating system that solves the most painful workflow problems in Indian MSME–Enterprise supply chains: manual invoice processing, opaque payment timelines, 43B(h) compliance risk, and disconnected accounting systems.
Mission
Replace manual, fragmented AP/AR workflows between MSMEs and large enterprises with a unified, AI-automated financial operating system — locking in both sides before activating third-party financing in Phase 2.
Phase 1 Users
User Type
What They Get
Key Pain Solved
MSME Supplier
Real-time invoice status, payment predictions, compliance protection, full AR accounting
No visibility on when they will get paid; no recourse on delayed payments
Large Enterprise Buyer
AI-automated 3-way matching, AP workflow, 43B(h) radar, dynamic discounting, full AP accounting
Manual invoice processing taking days; tax disallowance risk from late MSME payments
Strategic Rationale — Why Phase 1 First
Solves the cold-start problem: enterprises pay SaaS fees regardless of financiers
Builds 18 months of verified invoice data — the Phase 2 NBFC magnet
Each enterprise signed brings 50–200 MSMEs with zero MSME sales effort
Phase 1 target: 8–10 enterprises, ₹150Cr+ monthly invoice GMV
Phase 2 unlock: show NBFCs verified deal flow; they come to you

5. AI Pipeline Architecture
5.1 OCR Document Ingestion Pipeline
Invoices arrive as PDF uploads, image uploads, email attachments, or direct GSTN IRP pulls. All paths feed into a unified ingestion pipeline.
Stage
Technology
Detail
1. Intake
S3 + Lambda trigger
File lands in S3 → triggers Lambda → queues ingestion job in Redis Bull queue
2. OCR Extraction
AWS Textract (Forms + Tables)
Extracts key-value pairs and tables from invoice. Handles printed and scanned docs.
3. NLP Field Mapping
spaCy + custom NER model
Maps extracted text to structured fields: invoice_no, date, amount, line_items, GSTIN, HSN codes
4. Confidence Scoring
Logistic regression on field confidence
Each field gets a 0–1 confidence score. Fields below 0.8 flagged for human review.
5. GST Validation
GSTN API lookup
Validates seller/buyer GSTIN, verifies HSN codes, cross-checks against e-invoice portal
6. Human Correction
React UI correction interface
Low-confidence fields highlighted in yellow. AP team corrects inline. Corrections feed model retraining.
7. Storage
MongoDB + S3
Structured invoice document stored in MongoDB. Original file retained in S3 with 7-year retention.

6.3 MSMED Act Compliance Engine
The compliance engine automatically tracks every invoice from an MSME vendor and enforces payment deadline rules under the Micro, Small and Medium Enterprises Development Act.
Scenario
Rule
System Behavior
No written agreement
Payment within 15 days of invoice date
System sets payment_deadline = invoice_date + 15. Alerts at day 12, 14, 15.
Written agreement present
Payment within 45 days of invoice date
System sets payment_deadline = invoice_date + 45. Alerts at day 38, 43, 45.
Payment overdue
Compound interest at 3× RBI bank rate with monthly rests
Penalty calculator auto-runs daily. Shows compounding amount in AP dashboard.
43B(h) tax risk
Unpaid MSME invoices = tax deduction disallowance in enterprise’s ITR
43B(h) radar shows total disallowance exposure in ₹. Drives urgent action.
Penalty Interest Formula
// Compound interest with monthly rests at 3 × RBI Bank Rate
// RBI Bank Rate: fetched from RBI API, stored in config, updated when changed
 
function calculatePenalty(principal, rbi_bank_rate, overdue_days) {
  const annual_rate = rbi_bank_rate * 3;
  const monthly_rate = annual_rate / 12;
  const months = Math.floor(overdue_days / 30);
  const remaining_days = overdue_days % 30;
  
  // Compound for full months
  let amount = principal * Math.pow(1 + monthly_rate, months);
  
  // Simple interest for remaining days
  amount += amount * (annual_rate * remaining_days / 365);
  
  return {
    principal,
    interest: amount - principal,
    total_payable: amount,
    overdue_days,
    applied_rate_annual: annual_rate * 100 + '%'
  };
}
6.4 Yield Engine — Dynamic Discounting
Enterprises deploy surplus treasury cash to offer early payments to MSME vendors in exchange for a discount. No third-party financing required in Phase 1 — 100% funded by the enterprise’s own treasury.
Feature
Description
Treasury pool setup
CFO configures available early-payment budget (₹ amount). Can set auto-replenishment rules.
Invoice eligibility scoring
System scores each approved invoice for early payment eligibility based on vendor relationship, amount, days to due.
Discount proposal generation
Platform calculates optimal discount rate: fair to vendor (beats loan interest) + yields positive return to enterprise treasury.
Vendor acceptance workflow
MSME sees offer in dashboard: 'Reliance offers ₹1,84,000 today (discount: ₹1,200) vs waiting 28 more days.' One-click accept.
Yield calculation
Annualized yield = (discount_amount / invoice_amount) ÷ (days_accelerated / 365). Shown to CFO in yield dashboard.
Auto-offer rules
Enterprise sets rules: IF vendor_score > 70 AND invoice_amount < ₹50L AND days_to_due > 10 THEN auto-offer at [rate]%.
6.5 Samadhaan Escalation Assistant
Step
System Behavior
1. MSME triggers escalation
MSME clicks 'Escalate to Samadhaan' on overdue invoice. System validates: invoice > 45 days unpaid, vendor is MSME-registered.
2. Document generation

5. Case tracking

9. Security Architecture
9.1 Authentication & Authorization
Component
Implementation
Authentication
JWT (access token: 15min TTL) + Refresh token (30-day TTL, stored in Redis, single-use)
MFA
TOTP (Google Authenticator compatible) mandatory for admin roles, optional for all others
RBAC
5 roles: super_admin | company_admin | ap_manager | ap_clerk | view_only. Fine-grained permissions per resource.
API Authorization
AWS Lambda Authorizer validates JWT on every request before routing to backend
Company Data Isolation
All MongoDB queries include company_id filter injected by middleware. Cross-company data access impossible.
KYC Gating
Middleware blocks all financial actions until kyc_status = 'verified'
9.2 Data Security
Layer
Measure
Encryption at rest
AES-256 on MongoDB Atlas, RDS, S3. KMS key rotation every 90 days.
Encryption in transit
TLS 1.3 enforced. HSTS headers. Certificate pinning on mobile app.
PII handling
GSTIN, PAN, bank account numbers stored encrypted at field level (MongoDB CSFLE).
Financial data
Invoice amounts, payment details in encrypted fields. Only decrypted in application layer.
Audit immutability
Audit logs written to append-only MongoDB collection with no delete permissions. Backed up to S3 Glacier.
File security
All S3 invoice PDFs are private. Pre-signed URLs with 15-minute expiry for frontend access.
Data residency
All data stored in AWS ap-south-1 (Mumbai). No data leaves India. Compliant with RBI data localization guidelines.
9.3 Application Security
OWASP Top 10 mitigations in all API endpoints
Rate limiting: 100 req/min per IP (Redis sliding window); 1000 req/min per authenticated company
SQL injection: parameterized queries only in PostgreSQL accounting service
NoSQL injection: Mongoose schema validation prevents operator injection in MongoDB
File upload security: AWS Textract sandbox processing; no executable content allowed; virus scanning via ClamAV Lambda
Webhook signature verification: HMAC-SHA256 on all incoming webhooks (Razorpay, GSTN, banking APIs)
Dependency scanning: Snyk in CI/CD pipeline; blocks deploy if critical CVE found
